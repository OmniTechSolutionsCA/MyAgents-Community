# Tool Approval & Governance

When AI agents invoke tools that interact with databases, payment gateways, or filesystem resources, safe governance is critical.

## Tool Approval Policies (`IToolApprovalPolicy`)

Every tool call generated by a model passes through `IToolApprovalPolicy` before execution:

```csharp
using MyAgents.Core.Approvals;

var policy = new RuleBasedToolApprovalPolicy()
    // Read-only tools are automatically allowed
    .AllowTool("get_current_time")
    .AllowTool("search_knowledge_base")
    // Sensitive tools require explicit confirmation
    .RequireApproval("delete_customer_record")
    .SetDefaultDecision(ToolApprovalDecision.Reject("policy", "Tool is not in allowlist."));

services.AddSingleton<IToolApprovalPolicy>(policy);
```

## Approval Decisions

An `IToolApprovalGate` or policy can return:
- **`Allow`**: The tool executes immediately.
- **`Reject`**: The tool call is aborted, and a structured rejection message is returned to the model explaining the failure.
- **`RequiresApproval`**: Execution halts until an operator or approval gate provides an approval signal.

## Circuit Breaker Middleware

Protect downstream APIs from infinite loops or rapid model retries using `CircuitBreakerMiddleware`:

```csharp
var circuitBreaker = new CircuitBreakerMiddleware(new CircuitBreakerOptions
{
    FailureThreshold = 3,
    BreakDuration = TimeSpan.FromSeconds(30)
});
```
