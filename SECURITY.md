# Security Policy

## Supported versions

Before the first stable release, security fixes are made on the current
Community development branch. After the first stable release, the maintainers
will publish the supported release line here and in the release notes.

## Reporting a vulnerability

Please do not report suspected vulnerabilities in public issues or pull
requests. Use GitHub's **Report a vulnerability** option on the repository's
Security / Advisories page. If that option is unavailable, email
[brucebeckley@omnitechnologysolutions.tech](mailto:brucebeckley@omnitechnologysolutions.tech).

Include the affected version or commit, impact, and a minimal reproduction when
possible. Please allow maintainers a reasonable opportunity to investigate and
prepare a fix before public disclosure. Do not include real credentials,
customer information, or other sensitive data in a report.

Before the Community repository becomes public, maintainers must enable and
verify GitHub private vulnerability reporting and monitor the email address.
